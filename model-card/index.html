Research and engineering record · Chirag Taneja

What does it take to reproduce a foundational language model—not by fine-tuning an existing checkpoint, but by constructing the network, preparing the corpus, and carrying a random initialization through a complete pretraining run?

This project implements GPT-2 small as a compact, readable PyTorch system. It includes causal multi-head self-attention, pre-normalized residual blocks, tied token and output weights, distributed-aware data loading, bfloat16 training, deterministic evaluation, and exact checkpoint resume. The final model processed 9,999,745,024 tokens over 19,073 optimizer steps.

The result is intentionally modest in scale and unusually complete in documentation. The model, training record, public demo, metrics, checkpoint verification, recovery chronology, and source code can all be inspected independently.

Important

This is a base completion model—not a chatbot.

It was not instruction-tuned, preference-aligned, or safety-tuned. It predicts plausible continuations and should not be expected to follow conversational instructions reliably.

02 · Architecture

A small Transformer, shown all the way through.

GPT-2 is a decoder-only Transformer: every token can attend only to itself and earlier tokens. The implementation uses learned token and position embeddings, twelve identical pre-LN Transformer blocks, a final layer norm, and a vocabulary projection whose weights are shared with the input embedding table.

03 · Data

Ten billion educational tokens, verified shard by shard.

Training used the FineWeb-Edu sample-10BT configuration. Documents were encoded with the GPT-2 tiktoken vocabulary, prefixed with the end-of-text token, stored as compact uint16 arrays, and divided into 100 verified shards.

Ordered loading

Shard names are validated and numerically ordered before training. A malformed, duplicated, or missing shard causes a preflight failure rather than an expensive partial run.

Deterministic position

DataLoaderLite records the rank-zero data position plus batch, sequence, and world-size metadata, allowing every distributed rank to reconstruct its exact position after resume.

Data evidence

The finalized manifest records 9,953,989,344 unique prepared tokens across 100 shards; the final shard is partial. Training processed 9,999,745,024 tokens, including a 45,755,680-token loader wrap—about 0.46% of the prepared corpus.

FineWeb-Edu is filtered web data, not a curated truth set. The run did not perform a separate memorization, demographic-bias, or personally identifiable information audit of the training corpus.

04 · Training

A production recipe small enough to audit.

Each optimizer step aggregates 32 micro-batches of 16 sequences × 1,024 tokens, producing an effective batch of 524,288 tokens. The run uses AdamW, bfloat16 autocasting, gradient clipping, linear warmup, and cosine learning-rate decay.

06 · Reliability

The run survived because state was treated as a product.

The most consequential engineering work was not another model layer. It was making a multi-hour paid run recoverable: atomic local checkpoints, complete optimizer and RNG state, verified uploads, bounded retries, resumable downloads, and a latest pointer that advances only after integrity checks pass.

08 · Intended use and limitations

Useful as a learning artifact. Limited as a language system.

Appropriate use

Research and education

  • Studying a readable GPT-2 implementation.
  • Reproducing training and checkpoint mechanics.
  • Exploring base-model text continuation.
  • Benchmarking small-model infrastructure.
Out of scope

Autonomous or high-stakes use

  • Conversational instruction following.
  • Medical, legal, financial, or safety decisions.
  • Unsafeguarded public content generation.
  • Claims requiring factual reliability.
01

Scale

124M parameters and one approximately 10B-token pass are not competitive with modern frontier systems.

02

Alignment

No instruction tuning, preference optimization, refusal training, or dedicated safety tuning was performed.

03

Content risks

Outputs may be incorrect, incoherent, biased, unsafe, or stylistically derivative of pretraining data.

04

Evaluation coverage

HellaSwag is the only full downstream benchmark; no broad safety, bias, memorization, or toxicity suite was run.

05

Evidence window

The committed scalar history covers the final continuation segment, while terminal metrics come from the verified final checkpoint.
